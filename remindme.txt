GD32F310C8T6为72MHZ 8K ram + 64K flash
GD32F330CBT6为84MHZ 16K ram + 128K flash


flash布局：
0x08000000 + 28K  bootloader（26K代码 + 2K metadata）
0x08007000 + 50K  app
0x08013800 + 50K  stage

关于elf产物
app 第一个可执行段在 0x08007000；0x08000000 是 bootloader
.data .bss 在flash中位于上面那个可执行段后面，但是会被加载到2M地址处.bss不占文件空间
.heap_stack紧跟其后，这个节不占文件空间

ram的使用情况，按顺序
.data 是有初值的变量
.bss 是FreeRTOS ucHeap 4K configTOTAL_HEAP_SIZE预留的堆 + 
代码定义的没有初始化的变量, 当前约9.8K
.heap_stack是newlib malloc堆1K + MSP 栈1K（Makefile __stack_size=0x400）
当前约11.9K/16K，未超

启动流程:
复位后先运行 0x08000000 的 bootloader；bootloader 校验/拷贝 stage 后跳 app。
app 自己的启动流程：从 app 向量表获取 _sp 和 Reset_Handler，然后执行。
1. 复位，BOOT 选择主 Flash → Flash 别名到 0x00000000。
2. CPU 从 0x00000000 取 MSP = _sp，从 0x00000004 取 PC = Reset_Handler。
(flash开头节是.vectors 该节的头两个值就是_sp和Reset_Handler)
3. Reset_Handler 重设 SP为ram中的值，把 .data 从 Flash 拷到 RAM，把 .bss 清零。
.bss和.heap_stack不用拷贝，它们在文件中没有内容，只需要清理对应内存即可
4. SystemInit() 调用 nvic_vector_table_set(NVIC_VECTTAB_FLASH, 0)，即 SCB->VTOR =
0x08000000（system_gd32f3x0.c:307-310、gd32f3x0_misc.c:116-120）。此后中断直接按
Flash 的 0x08000000 取向量，不再依赖 0 地址别名。
5. 进入 main()。
不必担心访存是否正确，由于链接脚本，链接器知道各个节最终在内存中的位置

bin:
.bin文件单纯是可加载段，也不会额外补0

唯一需要copy的.data节的lma是链接脚本的_sidata,vma 是_sdata，这样就知道拷贝时的地址

外设使用情况
usart0
dma ch1用于从 buffer 到usart tx发送命令
dma ch2用于从usart rx 搬运接收命令到 buffer
TODO 下载的时候如果是发送128字节就等待回应，不用改ch2, 解析帧时从buffer运到flash即可

关于dma_total和read_total
它们都可以正确绕回，dma_total仅用于得到和read_total的差值
read_total还用于得到在buffer中的pos,只要bufffer的size是2的n次方，pos总能正确绕回

关于版本
app 镜像里有 fw_version_str 节(app 基址 +0x150，32字节字符串)
和 fw_version_num 节(app 基址 +0x170，共两个字节，低地址是 major，高地址是 minor)
